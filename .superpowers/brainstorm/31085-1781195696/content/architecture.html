Two-Tier Verification Architecture

CodeInsight V2 — Synthetic Classroom + Playwright E2E

System Architecture Diagram
A

Tier A: Backend Simulator

/simulation/ — API-driven semester run. 50 student personas, 3 cycles (Baseline → Stress → Adversarial). Bypasses browser. Tests DB concurrency, sandbox stability, CDS calculation.

  • personas.js — 4 performance tiers + instructor
  • studentGenerator.js — C++ AST normalizer + CodeNet matching
  • automationRunner.js — Multi-cycle Axios execution loop
  • validator.js — Queries DB → SYSTEM_HEALTH_REPORT.md
B

Tier B: Playwright E2E

/e2e/ — Browser automation with real pointer inputs, typing events, dynamic dashboard transitions. 1 Instructor + 1 Student context.

  • playwright.config.js — Headless localhost config
  • classroomWorkflow.spec.js — Auth → Join → Submit → Instructor Dashboard
  • Auth Gate, Join Code Gate, Monaco Editor flow, Heatmap rendering

Integration Layer

package.json scripts:
test:simulation → node simulation/automationRunner.js && node simulation/validator.js
test:e2e → npx playwright test

Shared infrastructure:
Both tiers target http://localhost:5000/api (backend) and http://localhost:5173 (frontend)
