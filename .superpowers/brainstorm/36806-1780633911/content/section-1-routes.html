Section 1 — Architecture & Routes

Approach B: Hub + Drill. CDS is the connective tissue across every detail page. Every analytics surface must answer an educational question.

DESIGN PRINCIPLE 01 — INSIGHT-FIRST ANALYTICS
Every chart, graph, heatmap, and table in CodeInsight must answer one of four educational questions. If it doesn't, it doesn't ship.
1. What is happening?  Descriptive
2. Why is it happening?  Diagnostic
3. Who needs help?  Prioritization
4. What action should be taken?  Prescription

Architectural shape

  • Frontend: React 18 + Vite + React Router v6. Existing services (Monaco, AuthContext) preserved. New design tokens + component library layered on top.
  • Backend: Node.js + Express. All 50+ endpoints stay. One new endpoint: GET /api/analytics/section/:id/hub aggregates the instructor command-center payload in a single round trip (avoids waterfall).
  • Database: 12 tables unchanged. Add 1 table: evaluation_responses (ISO/IEC 25010 instrument storage).
  • Auth: JWT, role-gated routes via a single <RoleGuard roles={['instructor']}> wrapper.
  • Visualization: D3.js for the heatmap (custom SVG, ~5KB), Chart.js for distribution/trend lines, vanilla CSS for everything else. No Recharts (per thesis).

How insight-first is enforced in the architecture

  • Every analytics endpoint returns a summary field alongside raw data — a one-sentence plain-English conclusion generated server-side from the data (e.g. "Functions has the highest avg CDS (0.62); 14 of 47 students are in High difficulty"). The client renders this summary as a chart caption by default.
  • Every chart component takes a required insight prop. If absent, the component renders in "raw mode" with a console warning (dev) and a visible "Interpretation missing" badge (prod) — fails the principle's check.
  • The instructor command hub displays 4 prioritized cards, one per insight question, before any raw chart. "What is happening → Why → Who → Action" is the page's reading order.
