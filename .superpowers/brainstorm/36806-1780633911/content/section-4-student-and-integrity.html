Section 4 — Student Learning Journey & Integrity Dashboard (v1)

Two more surfaces, same v3 discipline. Student Journey answers the same 4 questions, but to the student: What should I work on? Why am I stuck? Where do I stand? What's next? Integrity Dashboard is the investigative surface — neutral, evidence-first, no automatic consequences, always human-in-the-loop. Both reuse Confidence, Pattern, Impact, Signals-as-Pedagogy, and "Why am I seeing this?".

SURFACE A — STUDENT LEARNING JOURNEY
Three routes: /student/today (the daily hub) · /student/progress (my 7-axis mastery + history) · /student/recommendations (the next move). The student's own data, reflected back. Never a leaderboard. Never a class rank. Only "you vs your last week" and "you vs the class concept avg" — both with the same K-tier honesty.
Anti-patterns the student surface must avoid: comparing students to each other · showing raw class rank · "you are behind N students" · any framing that turns analytics into a grade-shame loop. The student sees their own trajectory and the concept, never the cohort ranking.

SURFACE B — INTEGRITY DASHBOARD (INVESTIGATIVE, NOT PUNITIVE)
Integrity flags are evidence, not accusations. The dashboard is a forensic surface: every flag has the rule that fired, the evidence (z-score, line spike, paste sequence, test match), and a clear set of instructor actions. The system never auto-fails, auto-zeros, or auto-reports. The instructor's judgment is the terminal state.
Three epistemic commitments, restated for the spec:
1. A flag is a hypothesis, not a verdict. The dashboard presents evidence; the instructor decides.
2. Pattern, not accusation. "Submitted output literal matches expected for 3 hidden test cases" — not "student cheated".
3. Student transparency. /student/integrity shows the student the same flags, in plain language, with an appeal path. See student-side mockup.

Anatomy of Section 4 (recap of what v1 introduces)

  1. Student /today — the 4 questions restated for the student, today's exercise, the pattern of stuckness (interpreted, with the "Why am I seeing this?" affordance), the 7-concept mastery bars, 3 small next-move cards, and a *brief* signals-as-pedagogy panel (only 2 of 4 signals, all interpreted, no raw counts).
  2. Student /progress — your CDS-over-time vs class avg-as-faded-reference (never a leaderboard), and a per-concept 6-week trend list with sparklines. The class avg is shown as a dashed line, explicitly labeled "not a rank".
  3. Student /recommendations — 3 prioritized cards: priority / optional / stretch. Each carries a Pattern, a confidence badge, and a "Why am I seeing this?" affordance. Rule-selected, not LLM-personalized.
  4. Instructor /integrity — the flag queue. Each flag: rule name + "Why am I seeing this?" link, evidence (z-scores, growth, paste sequence, literal match), confidence, pattern observation, and a row of instructor actions. No auto-fail, no auto-zero, no auto-report. The instructor's judgment is the terminal state.
  5. Student /integrity — the same flag, reflected back to the student in plain language. Three affordances: request 1:1, appeal, read the full rule. Transparency as a feature.

Privacy boundary (single line for the spec, expanded for the thesis)

The student sees interpreted signals about their own learning. The instructor sees behavioral telemetry for the class. The student never sees another student's data. The class never sees a leaderboard. Raw behavioral counts (e.g. "you switched tabs 47 times") are not surfaced to students — only the interpretation ("you might be stuck on boundary cases") is. This is the surveillance-vs-pedagogy boundary, enforced at the data layer, not just the UI layer.
