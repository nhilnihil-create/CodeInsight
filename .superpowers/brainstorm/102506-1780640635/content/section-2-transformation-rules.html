Section 2 — Component transformation rules (desktop → mobile collapse)

The single most important section. Defines the deterministic transformation from each desktop component to its mobile counterpart. The rule is: one component, two render modes, switched by CSS or by the useIsMobile() hook for chart-heavy components only. Tablet (640–1024px) and desktop share the same render path; only phone (<640px) gets the transformation.

Rule 1 — Chart degradation

  • Phone never instantiates a D3 SVG larger than 200×200px. Heatmap / radar / multi-series → summary widget or sparkline.
  • Sparklines are pre-aggregated server-side (we already do this for KPI deltas) — the client renders them with a tiny inline SVG, no D3 dependency.
  • D3 fallback strategy: if (useIsMobile()) return <SummaryView />; else return <D3Chart />; at the top of each chart component. The D3 import is dynamically loaded and skipped on phone (no D3 in the phone bundle for those components).
  • Drill to full chart: every summary widget ships with a "View full analysis →" link that opens the desktop-rendered chart at its full route (e.g., /concepts/:id). The user accepts the page is optimized for tablet+ here.

Rule 3 — Touch & gesture surface (phone only)

  • Tap targets ≥ 44×44. Buttons get 12px vertical padding minimum; list rows get 56px height minimum.
  • Swipe gestures: swipe-left on a queue row = "snooze" or "dismiss" (with undo toast). Swipe-right on an integrity flag = "approve / clear". Both undoable.
  • Long-press: long-press on a CDSPill shows the trend sparkline + Wilson CI. Long-press on a ConceptRow shows the 4-week history sparkline.
  • Pull-to-refresh: only on top-level role pages (Command, Today, Overview). Implemented with a 60px threshold. No library — 20 lines of pointer-event handlers.
  • No hover-only affordances: any desktop hover state (e.g., "hover to see tooltip") gets a tap-equivalent on phone. Tooltip on long-press is the canonical pattern.
  • Safe-area-inset: bottom tab bar respects env(safe-area-inset-bottom) for iOS home indicator. Top app bar respects notch on landscape.

Rule 4 — Performance budget (phone only)

  • Initial JS bundle (phone route): ≤ 200KB gzipped. Monaco is lazy-loaded only on /student/exercises/:id and never on the initial bundle.
  • D3 imports: dynamic import('d3') on chart components, behind a viewport check. Phone never loads D3 for components that render as summary.
  • No full-page re-renders: route changes use React.lazy + Suspense with route-level code splitting. The mobile entry bundle is the role-resolved layout + the role's primary widget.
  • Image / chart lazy-load: charts off-screen get loading="lazy" equivalent via IntersectionObserver. Tap-to-load for embedded heavy D3 grids.
  • CSS containment: contain: layout on cards to limit reflow when RiskBadge or CDSPill changes.
